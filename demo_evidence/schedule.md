# Поиск конфликтов расписания

**Синтетический демо-артефакт Kuskon AI, подготовлен с Codex.** Он используется как общий пример в вымышленных профилях. Это не авторская работа реального школьника и не доказательство его навыков.

**Задача:** найти все пары пересекающихся занятий в расписании одного дня. Код — `schedule.py`; внешних библиотек и сети не требуется.

```bash
python demo_evidence/schedule.py
```

Команда запускает **9 тестов**, включая несколько проверок ошибочных входных данных. Для использования функции:

```python
from demo_evidence.schedule import find_conflicts

print(find_conflicts([
    ("Python", "09:00", "10:00"),
    ("Дизайн", "09:30", "10:30"),
    ("Математика", "10:30", "11:30"),
]))
# [('Python', 'Дизайн')]
```

## Решение

Время `HH:MM` переводится в минуты от начала дня. Для каждой пары проверяется `max(начал) < min(концов)`. Интервалы **полуоткрытые**: `[начало, конец)`. Поэтому занятие до 10:00 не конфликтует с занятием, начинающимся ровно в 10:00. Вложенные и одинаковые интервалы разных занятий конфликтуют.

| Проверка | Ожидаемый результат |
|---|---|
| 09:00–10:00 и 09:30–10:30 | Одна пара конфликтов |
| 09:00–10:00 и 10:00–11:00 | Конфликтов нет |
| Непересекающиеся занятия в обратном порядке | Конфликтов нет |
| Два занятия с одинаковым временем и разными именами | Одна пара конфликтов |
| Занятие целиком внутри другого | Одна пара конфликтов |
| Три взаимно пересекающихся занятия | Все три пары |
| Пустое расписание или одно занятие | Пустой список |
| Неверный формат, несуществующее время, нулевая длительность, переход суток | `ValueError` |
| Повтор имени, пустое имя или неверная структура входа | `ValueError` |

## Ограничения и рефлексия

Алгоритм делает до `n × (n − 1) / 2` сравнений: время `O(n²)`, память для результатов до `O(n²)`. Для небольшого учебного расписания это понятное решение. Имена занятий должны быть уникальными; допустимо время от 00:00 до 23:59, начало раньше конца. Нет дат, часовых поясов, перехода полуночи, кабинетов и преподавателей: считаем все занятия ресурсами одной группы. Следующий шаг — добавить явные ресурсы и тесты для нескольких дней.

Проверки автоматические, не исследование с пользователями. В приложении возможны разные синтетические оценки одного общего артефакта — они демонстрируют механику паспорта, а не реальные результаты школьников.
