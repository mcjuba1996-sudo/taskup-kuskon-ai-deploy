# Запись на встречу: прототип трёх состояний

**Синтетический демо-артефакт команды Kuskon AI, подготовлен с Codex.** Общий пример для вымышленных профилей, не работа реального школьника. Настоящей встречи, регистрации и отправки уведомлений нет.

Откройте `signup.html` в браузере. Один HTML-файл содержит стили и JavaScript; не требует сервера, библиотек, подключения к сети или личных данных.

## Три состояния

1. **Запись.** Описание бесплатной вымышленной встречи, длительность, выбор одного из двух временных слотов. Пустой выбор не проходит встроенную проверку формы.
2. **Подтверждение.** Показаны выбранное время, длительность и часовой пояс. Можно отменить запись; прямо объяснено, что это демонстрация.
3. **Отмена.** Запись очищается без запроса причины. Кнопка возвращает к форме, чтобы выбрать время заново.

После перезагрузки открывается первоначальное состояние. Используется только память страницы: нет cookies, `localStorage`, сетевых запросов, аналитики или сохранения участников.

## Почему такие решения

Для демонстрации не нужны имя, телефон, email и произвольный текст. Слот выбирается из списка, поэтому понятнее, что подтвердилось. Отмена доступна без объяснения причины. У полей есть подписи, кнопки доступны с клавиатуры; смена состояния переносит фокус на заголовок и обновляет `aria-live`. Верстка рассчитана на узкий экран, без внешних шрифтов.

## Проверка прототипа

| Действие | Ожидаемое поведение |
|---|---|
| Открыть файл | Видна только форма; выбор времени пуст |
| Нажать подтверждение без времени | Форма остаётся открытой, браузер требует выбор |
| Выбрать первый слот и подтвердить | Видно подтверждение с выбранным временем |
| Нажать отмену | Видно состояние отмены; прежний слот очищен |
| Записаться заново, выбрать второй слот | Новый слот отражается в подтверждении |
| Перезагрузить страницу | Состояние сброшено, регистрация не сохранена |
| Пройти клавиатурой и открыть узкое окно | Поля доступны, кнопки и текст помещаются |

Это сценарий технической проверки. **Исследование с реальными пользователями не проводилось.** Нельзя утверждать, что интерфейс улучшил конверсию, прошёл полную проверку доступности или удовлетворяет требованиям реального сервиса регистрации.

Следующий шаг после хакатона: наблюдать, как участники понимают подтверждение и отмену, затем проверить настоящий процесс согласий и хранения. В текущем примере намеренно нет реальных персональных данных и внешних действий.
