# TaskUp Talent · SANA Team

**Результат работы и понимание решения видны отдельно.** MVP для трека HackHub «Талант до вуза» на Gambit Hackathon 2026. Выбранный разрыв — **доверие**: проверяем гипотезу, что координатору корпоративной проектной IT-программы нужны понятные свидетельства навыков и личного вклада школьника для отбора участников.

Прототип поддерживает школьников **8–11 классов** из Актюбинской области: собственный проект, мини-задание, оценка результата и добровольный показ портфолио. Восемь кабинетов отражают участников рынка из кейса. Школьник пользуется продуктом бесплатно; личный отчёт доступен даже без покупателя.

Первоначальная коммерческая гипотеза остаётся узкой: **корпоративная проектная IT-программа с отбором школьников 9–11 классов**. Её координатор проверяет результат, при необходимости запрашивает объяснение и небольшое изменение, затем собирает список кандидатов. Наличие кабинетов вузов, агентств и фондов не означает, что их спрос или готовность платить уже проверены.

**Статус:** демонстрационный прототип на синтетических данных. Подтверждённых интервью, оплат и партнёрств пока нет. Это переработка предыдущего MVP TaskUp: прежний сценарий сохранён в `legacy_app.py`.

Рабочее демо: [taskup-sana.streamlit.app](https://taskup-sana.streamlit.app/). Streamlit подключён к ветке `main`; трёхъязычный интерфейс опубликован через [PR №4](https://github.com/mcjuba1996-sudo/taskup-sana-team.git). На публичном сайте проверены русская главная страница, английский кабинет вуза, переход в «О проекте» и переключение на казахский с сохранением профиля и страницы. Локально прошли **131 тест за 67,458 секунды**, включая 8 новых тестов локализации, и отдельный проход **99 сочетаний роли, страницы и языка в AppTest**. После последних исправлений переводов повторно прошли 8 тестов локализации. Казахская мобильная вёрстка проверена локально; публичная версия — на широком экране. ## Три языка

Вверху всех экранов нового TaskUp Talent доступен переключатель **Қазақша / English / Русский**. Переведены интерфейс восьми кабинетов, демонстрационные задания и рубрики, подписи паспортов и отчётов, а также три демонстрационных Markdown-отчёта. Переводы загружаются из локальных каталогов и работают офлайн, без API-ключей и внешнего сервиса перевода.

**Сохраните заполненную форму перед сменой языка.** Переключение меняет язык интерфейса; введённые пользователем названия, описания, ответы и обратная связь хранятся и показываются на исходном языке. Автоматически переводятся только точные совпадения с подготовленными демостроками. Язык интерфейса не меняет роль, права доступа, критерии или сохранённую работу.

Полный исследовательский TXT-пример остаётся на русском; ссылка в других языках прямо помечена «Russian» / «орысша». Технические артефакты — Python-код, CSV и HTML-прототип — сохранены в исходном виде. В переводах демонстрационных отчётов исходные блоки кода и данных не изменены.

## Участники рынка

| Кабинет | Действия в прототипе |
|---|---|
| Школьник | Личный проект, сдача задания, доработка, защита, решение по записям источников и приглашениям |
| Родитель / законный представитель | Согласие на показ связанного ребёнка, обзор отправленных работ и приглашений |
| Вуз | Задания для довузовской программы, оценка, поиск по доступным работам, приглашение |
| Образовательное агентство | Разбор учебного проекта, поиск подходящих профилей и приглашение на консультацию |
| Компания | Задания и отбор в образовательную или CSR-программу |
| Фонд / грантодатель | Задания и поиск участников региональной программы или отбора |
| Школа | Записи о результатах только своих демоучеников; указание основания и отзыв записи |
| Организатор конкурса | Записи о результатах только своих демоучастников; указание основания и отзыв записи |

Четыре типа покупателей используют общий цикл задания, проверки, каталога и приглашения с разными целями. Школа и организатор выступают источниками сведений; родитель управляет только собственным согласием. Полная схема доступа и ограничения — [участники и роли](docs/participants.md).

## Основной сценарий

1. Школьник выбирает задание, изучает фиксированную шкалу и отправляет ссылку, версию исходников, описание результата и личного вклада.
2. Покупатель открывает результат. Для каждого критерия записывает наблюдаемое свидетельство, оценку, своё имя/роль и ограничения проверки.
3. При необходимости возвращает работу на доработку. Школьник отправляет новую версию; прежняя остаётся в истории, новая оценка начинается заново.
4. Для проверки понимания покупатель задаёт вопрос и небольшое изменение. Школьник объясняет решение и прикладывает результат изменения; проверяющий сохраняет наблюдения и отдельный вывод по пониманию.
5. После принятия результата школьник видит паспорт: оценки и свидетельства, проверяющий, статус понимания, ограничения и история версий.
6. Школьник разрешает показ профиля; для связанного профиля родитель отдельно даёт своё демонстрационное согласие. В прежних демопрофилях без родительской связи оба согласия моделируются чекбоксами с явным пояснением. Покупатель видит профиль только при обоих согласиях и принятой работе.
7. Школьник принимает или отклоняет приглашение. Внешние сообщения не отправляются.

Школа или организатор дополнительно может выдать запись из своего списка участников. Школьник принимает или отклоняет её. Принятая запись видна покупателю только при уже доступном профиле; она не заменяет принятую работу и не включает согласия. Источник может отозвать запись. Это заявление указанного источника с основанием, а не независимый сертификат платформы.

Пошаговый проход ролей — в [сценарии демонстрации](docs/demo-walkthrough.md).

## Что именно подтверждает паспорт

**Оценка результата** отвечает на вопрос, соответствует ли конкретная работа критериям задания. **Проверка понимания** показывает, как участник объяснил решение и выполнил запрошенное изменение. Эти статусы не подменяют друг друга: результат может быть принят без защиты, но паспорт тогда прямо сообщает, что понимание не проверялось. Если защита уже запрошена, принять работу нельзя до успешного завершения этой проверки; можно вернуть её на доработку.

У каждой оценки есть отдельное текстовое свидетельство по критерию. Сохраняются имя, роль, организация проверяющего, дата и ограничения. В демо эти сведения вводятся вручную и не удостоверяют личность эксперта. Защита сохраняет вопрос, запрос изменения, ответ, ссылку, версию результата и наблюдения проверяющего. Она не является прокторингом или универсальным доказательством авторства.

История сохраняет снимки отправок, доработок, оценок и защиты; прежние снимки нельзя переписать через интерфейс приложения. При новой сдаче старые оценки и вывод защиты не переносятся на новую версию. Ссылки ведут на внешние материалы: указанный commit/номер версии — записанное значение, а не автоматически проверенный хеш или архив исходников. Старые демоданные не получают вымышленные сведения о проверяющем задним числом.

Паспорт относится к конкретной работе и проверке. Он не удостоверяет личность, исключительное авторство кода или универсальный уровень таланта. ИИ не подтверждает достижения и не выбирает участников.

## «Мой проект» без покупателя

Школьник сохраняет существующую учебную работу, описывает личный вклад, инструменты и помощь, отмечает пункты самопроверки и скачивает Markdown-отчёт. Для черновика достаточно названия. Отчёт всегда помечен **«Самооценка. Внешняя проверка не проводилась»**; чекбоксы не дают баллов или статуса принятой работы.

Личный черновик не входит в каталог покупателей и не показывается родителю. Для передачи школьник выбирает подходящее задание и отдельно подтверждает отправку копии. Нужны ссылка, описание результата и вклада; последующие изменения личного проекта не меняют отправленную версию. Подробнее — [личные проекты](docs/independent-projects.md).

## Как считается оценка

Три критерия оцениваются человеком от 0 до 4. Их веса — 40%, 35% и 25%; формула: `балл = (оценка_1 × 40 + оценка_2 × 35 + оценка_3 × 25) / 4`.

Условия подтверждения: итог **не ниже 70/100** и **ни один критерий не ниже 2/4**. Критерии и их веса известны до отправки работы; нельзя менять шкалу после получения результата. При отрицательном решении остаётся обратная связь. Балл оценивает работу по конкретному заданию, а не сравнивает все школьные достижения между собой.

## Данные и ограничения демо

- Все участники, работы, оценки и организации в начальных данных вымышлены.
- Переключатель ролей — демонстрация сценария, **не авторизация**. Не вводите реальные персональные данные.
- Видимость подтверждённого паспорта требует двух демонстрационных согласий: школьника и законного представителя. Область показа включает принятые работы, прежние версии, ответы защиты, наблюдения проверяющего и принятые школьником записи источников. Переключатели не являются юридически действительным сбором согласий или проверкой родителя.
- В новой демонстрации родитель связан только с Нурай Е., 8 класс (обычно ID 106). Школьник не может изменить родительское согласие, а родитель — включить согласие школьника. Отзыв любого согласия скрывает профиль и убирает ожидающие приглашения; заказчик сохраняет доступ к работам на своих заданиях. Прежние профили без родительской связи сохраняют явно обозначенный режим моделирования двух согласий.
- Школа и организатор работают со своим демонстрационным списком. Принятие школьником записи означает согласие включить заявление источника в достижения, а не независимую проверку его достоверности. Отозванные записи исчезают из представления покупателя.
- Покупателю показываются только доступные в демо сведения о профиле и работе. Сырые телефоны, email и адреса несовершеннолетних не нужны; приглашения остаются внутри приложения.
- SQLite хранит состояние локально. При размещении на хостинге с временным диском данные могут быть потеряны; для реального запуска нужны авторизация, проверка согласий и внешняя БД.
- До пилота с настоящими школьниками требуется отдельная подготовка доступа, обработки данных и процесса экспертной проверки. Этот прототип не готов к публичному сбору данных детей.

## Бизнес-гипотеза

**100 000 ₸ за 30-дневный пилот** — непроверенная цена для одного корпоративного координатора: одна кампания, одно задание, до 100 регистраций и до 25 работ на проверке. Экспертов предоставляет покупатель; число участников и приглашений не гарантируется. Покупатель оплачивает организацию отбора; персональные данные школьников не продаются.

Цена и объём пилота должны быть проверены на интервью. Расчётный сценарий расходов — 81 000 ₸, остаток 19 000 ₸ до постоянных затрат и налогов; это не чистая прибыль. Польза для бюджета покупателя пока не измерена. Для вузов, агентств и фондов отдельные цены и подтверждённый спрос не заявляются. [Бизнес-модель](docs/business-model.md) содержит точный пакет, трудозатраты и недостающие доказательства; краткая версия — [Lean Canvas](docs/lean-canvas.md), каналы и цели — [план запуска](docs/launch-plan.md).

## Запуск

Целевая версия для локального запуска и деплоя — **Python 3.12**. Для нового сценария ключи API не требуются.

```bash
git clone https://github.com/mcjuba1996-sudo/taskup-kuskon-ai-deploy.git
cd taskup-kuskon-ai-deploy
git switch main
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

macOS/Linux:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Откройте `http://localhost:8501`. Если скачан архив подготовленной версии, пропустите клонирование и переключение ветки, откройте терминал в папке проекта.

Проверки в Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В macOS/Linux: `.venv/bin/python -m unittest discover -s tests -v`.

Для повторного размещения в Streamlit Community Cloud выберите репозиторий `mcjuba1996-sudo/taskup-kuskon-ai-deploy`, ветку `main`, входной файл `app.py` и Python **3.12**. Секреты API для нового сценария не нужны. Рабочая публикация уже использует эти настройки. Перед показом жюри пройдите кабинеты по [сценарию](docs/demo-walkthrough.md).
